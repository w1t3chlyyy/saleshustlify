# Hustlify: бот + мини-приложение для отдела продаж

Стек: Telegram Bot API, Vercel (статика + serverless), Supabase (Postgres + Storage), Qwen (DashScope), Vercel Cron / cron-job.org.

## Что внутри
- `api/bot.js` — вебхук бота: приветствие и кнопка мини-приложения
- `api/app.js` — весь API мини-приложения (одна функция, роутинг по `action`)
- `api/cron.js` — ежедневно пополняет базу бизнесов и сбрасывает истёкшие бусты
- `lib/` — Supabase, подписи и пароли, Qwen, поиск бизнесов, инструменты админ-агента
- `public/` — мини-приложение (Apple-стиль, ч/б, Unbounded + Montserrat)
- `supabase/schema.sql` — таблицы, атомарные функции, RLS, стартовые данные

## Запуск
1. **Supabase.** Создай проект, выполни `supabase/schema.sql` в SQL Editor. Возьми `Project URL` и `service_role` key. Твои таблицы товаров и кейсов уже есть: если называются не `products` и `cases`, поменяй `PRODUCTS_TABLE` / `CASES_TABLE`.
2. **Бот.** В @BotFather создай бота, получи токен. Свой Telegram ID узнай у @userinfobot и впиши в `ADMIN_TG_IDS`: при регистрации получишь роль admin.
3. **GitHub + Vercel.** Залей проект в репозиторий, импортируй в Vercel, добавь все переменные из `.env.example`. После деплоя поставь `APP_URL` = адрес проекта и передеплой.
4. **Вебхук и кнопка меню** (один раз, подставь свои значения):
   ```
   curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" -d "url=<APP_URL>/api/bot" -d "secret_token=<WEBHOOK_SECRET>"
   curl "https://api.telegram.org/bot<BOT_TOKEN>/setChatMenuButton" -H "Content-Type: application/json" -d '{"menu_button":{"type":"web_app","text":"Hustlify","web_app":{"url":"<APP_URL>"}}}'
   ```
5. **Cron.** Vercel Cron уже описан в `vercel.json` (раз в сутки, на Hobby это максимум). Если нужен внешний CronJob: `GET <APP_URL>/api/cron?key=<CRON_SECRET>`.

## Как это работает
- **Вход.** Регистрация и вход по логину и паролю, аккаунт привязывается к Telegram ID. Каждый запрос проверяется по подписи `initData` плюс токену. 5 неверных паролей — блокировка на 10 минут.
- **Обучение.** Разделы лежат в таблице `lessons` (markdown в `body`). Добавляй их через админку Qwen или прямо в Supabase. Раздел открывается после сдачи теста предыдущего (порог `quiz_pass_percent`, по умолчанию 70%). Тест Qwen генерирует под сотрудника и учитывает прошлые ошибки. Правильные ответы хранятся только на сервере.
- **Практика.** Qwen играет вредного клиента с случайным характером, знает товары и кейсы из твоих таблиц. После «Завершить сделку» отдельный вызов Qwen оценивает диалог. При успехе (`score >= 60`) начисляется `training_reward_coins` (20) и открывается кабинет.
- **База бизнесов.** Город → 15 бизнесов в сутки, которые ещё никому не выданы. Источник по умолчанию OpenStreetMap (бесплатно, без ключа). Для России охват заметно лучше у 2GIS: `PLACES_PROVIDER=2gis` и `GIS_API_KEY`. Яндекс Карты я не подключал: их условия ограничивают хранение данных поиска в своей базе.
- **Проверка работ.** Сотрудник отправляет описание и фото, админ принимает в разделе «Проверка» и сотруднику падают коины (`business_reward_coins`, 10) плюс уведомление в Telegram.
- **Процент с продаж.** Админ записывает продажу по ID бизнеса или логину. Ставка зависит от принятых работ за 30 дней (`percent_tiers`: 5 / 7 / 10 / 12%) плюс буст из магазина.
- **Магазин.** Товары в `shop_items`: промокоды, бусты ставки, свободные позиции (приходит уведомление админу).
- **Админ Qwen.** Доступ только для role=admin. Может читать и менять любые таблицы, коины, теги, настройки, делать рассылки и смотреть статистику. Удаления и рассылки требуют подтверждения в диалоге, каждое изменение пишется в `audit_log`.

## Важно знать
- `SUPABASE_SERVICE_KEY` только на сервере (Vercel env). RLS включён без политик, поэтому напрямую из браузера данные недоступны.
- Qwen-админ получает реальные права на запись. Проверяй, что именно он собирается удалить, прежде чем подтверждать.
- Рассылка за один вызов ограничена 1000 получателями и упирается в лимит времени функции 60 с.
- Покрытие OSM по телефонам в небольших городах РФ может дать меньше 15 бизнесов в сутки. Тогда включай 2GIS.
- Валюта выплат ₽ задана константой `CUR` в `public/app.js`.
